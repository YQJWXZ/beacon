# ADR-0001：暂时不引入 Grafana

- 状态：已接受
- 日期：2026-11-11
- 决策者：项目所有者
- 关联：SPEC §11「Grafana 决策门」

## 背景

MVP 的目标是「一台家里的机器 + 几台云主机」。指标已经在 VictoriaMetrics 里，查询能力通过 vmui 和 CLI 暴露。Grafana 会给更完整的面板，但也要多维护一个 150MB 级的服务、一套 dashboard JSON，以及版本升级。

SPEC 里预先定了三条触发条件，满足任一条才引入：

1. 需要在同一页对比 3 台以上主机的同一指标
2. 需要把面板分享给不看命令行的人
3. 需要固化 5 个以上常用视图，且每天都会打开

## 现状评估

| 条件 | 现状 | 判断 |
|---|---|---|
| 多主机同页对比 | 目前 1–3 台；vmui 多序列对比确实别扭，但频次是"偶尔查一次" | 未触发 |
| 分享给非技术用户 | 告警已经通过飞书卡片推送，非技术用户不需要看面板 | 未触发 |
| 5+ 固定视图、每天打开 | 日常入口是飞书告警 + `beacon audit/flow/top`；没有每天开面板的习惯 | 未触发 |

另外两个反向因素：

- vmui 与 VM 同源，升级 VM 不需要同步升级面板
- 引入 Grafana 后，告警仍然走 vmalert/Alertmanager，Grafana 只承担"看"，收益集中在视觉上

## 决定

**MVP 不引入 Grafana。** 看板需求用 vmui（临时查询）+ CLI（固定动作）覆盖。

## 后果

- 少维护一个服务，中心资源占用保持在 ~300MB
- 多主机对比、历史回看的体验弱于 Grafana
- 卡片里的「查看曲线」打开的是 vmui，链接格式与 Grafana 不同

## 重新评估的触发条件

任一条件出现即重新评估，不必等到版本迭代：

1. 被监控主机数 ≥ 3 且需要横向对比
2. 出现非技术使用者要自己看趋势
3. 每周手动拼同样的查询 ≥ 3 次

重新评估时优先考虑 **Grafana + VM 数据源**（不引入 Prometheus），并只维护 3 个 dashboard：主机总览、网络与流量、审计与暴露面。
